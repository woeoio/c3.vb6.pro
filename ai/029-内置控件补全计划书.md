## 三、核心决策（要拍板）

### D1 集合与"成员对象"怎么表示（`ListItems` / `Nodes` / `Buttons` / `Panels` / `ListImages` / `ColumnHeaders`）

VB6 的写法绕不开对象：`Set itm = ListView1.ListItems.Add(, , "张三")`、`itm.SubItems(1) = "销售部"`、`For Each n In TreeView1.Nodes`、`StatusBar1.Panels(1).Text = "就绪"`。三条路：

- **(a) RTL 里手写 IDispatch 对象 + 合成 VB 类型名**。成员对象是一个带 name→dispid 表的真 `IDispatch`（RTL 已有 `ComObj_Invoke` 那一套可借），`Node`/`ListItem`/`Panel`/`Button` 这些类型名由编译器内建登记。属性读写走今天已经通的晚绑定通道（`vb6_ComGetProp` / `vb6_ComCall`），`Set`/默认属性/命名实参天然生效。
  代价：每个成员对象一族要写 C 版 dispatch 表；`For Each` 要集合可枚举（`_NewEnum`）。
  好处：**语法面最完整**，且顺带把 022/D71 那条"工程内类交给 `As Object` 点不到成员"的缺口需要的同一套东西建起来。
- **(b) cgen 特例直译**：`ListView1.ListItems.Add(a,b,c)` 在编译期折成 `vb6_LV_AddItem(h, ...)` 返回一个"节点索引值"，成员属性再按表达式类型二次特判。
  代价：`Set itm = …` / `itm.SubItems(1) = …` / `For Each` 每一条都要新特例，特例之间互相打脸；这正是历史上 `vb6_CStr` 那一族长出一百多个 Fix 的形状。**不推荐**。
- **(c) 降级口径**：v1 只做"按下标/按键取属性"的直调面（`ListView1.ListItems(1).Text`、`Nodes.Add(...)` 不 `Set`），对象变量与 `For Each` 明写不做。
  好处：批次砍一半；代价：与 VB6 语法不完全对齐（用户要的就是"语法上是 vb6"）。

**推荐 (a)**，但分两步落地：先在 C29-3 用 ImageList 的 `ListImages` 把这套对象机制立起来（它最小：只有 Add/Remove/Clear + Index/Key），再让后面六个控件复用。

### D2 事件参数里的类型名怎么写

`Private Sub TreeView1_NodeClick(ByVal Node As MSComctlLib.Node)` —— 点号前缀的类型名在没有那份 typelib 时今天会当未知符号。三个选项：① 两种写法都收（`As MSComctlLib.Node` 折算到内建 `Node`）；② 只收 `As Node`；③ 只收 `As Object` / `As Variant`（晚绑定，编译器不管类型）。
**推荐 ①**：文档里的示例（Toolbar/TreeView/ListView 三份）用的都是 `MSComctlLib.` 前缀写法，收不下就等于示例代码编不过。

### D3 GUI 控件的判据手法（否则"门"只是不崩）

- 把子窗口探针入册成 `tests/ctrl_probe.ps1`：起 exe → `EnumChildWindows` 取（类名, 文本, 可见, 矩形）→ 断言；可选 `SendMessage`/`BM_CLICK`/`TCM_SETCURSEL` 注入一次交互，再由程序自身 `Debug.Print` 打 stdout 针。
- 会阻塞的（CommonDialog 六个 `Show*`）：程序自己起一个 `SetTimer`/线程，用 `FindWindowW(#32770)` + `EndDialog(IDOK/IDCANCEL)` 自关，断"对话框确实出现 + 取消能触发 `cdlCancel`(32755) + `CancelError` 语义"。
- **x86 必做**：控件线是 32 位 VB6 的主场，且 comctl32 v5/v6 清单依赖在这条上最容易露馅（022 的老教训：门只测默认架构）。

### D4 Data / OLE 容器：明确不做（写死，避免每轮复议）

理由见 §五。

### D6 OCX 那条路一律换掉（2026-09-26 用户定调，写死、后面每批不再复议）

用户原话："我是让你原生实现，只是语法一样，不要用外部 ocx"、"后面的所有控件都一样，因为原来的 ocx 不支持 64 位"。
⇒ 本线剩余每一类（CommonDialog / ImageList / Toolbar / StatusBar / SSTab / ListView / TreeView）都按同一口径做：

- **默认路必须是原生 API**（comctl32 公共控件类 / comdlg32 / shell32 …），`cgen_expr_member_form_builtin.inc` 里  那一组"ActiveX 控件按 COM 后期绑定"（`ImageList / Toolbar / StatusBar / CommonDialog` → `CoCreateInstance` +  `vb6_ComCall`）必须**逐类摘出去**，摘一类少一类。
- 为什么必须摘：MSCOMCTL.OCX / MSComDlg.OCX 这类 32 位 OCX 在 x64 进程里 `CoCreateInstance` 直接失败 ⇒  今天这些控件在 64 位下是**静默空转**（029 §九 的 C29-9 测量给了实测读数：属性读回全空、`ShowOpen` 不出现、  退出码照旧 0）。留在默认路上，"门绿"就没有意义。
- §五-3 那条"真 OCX 宿主不拆"仍然有效，但**只作为显式选择**：谁在 `.frm` 里真拿注册了的 OCX 类名来、  或走 `Declare`/后期绑定主动点名，`vb6_OcxHost_Create` 那条路照旧在；它不再是任何内置控件的默认行为。
- 依赖面：只经 `LoadLibrary` + `GetProcAddress` 取（照 `vb6_di_com_stubs.c` 里 GDI+ 那条例子），  **不新增 import lib**（§六-3 的工具链依赖面不动）。

## 五、明确不做（v1 写死）

1. **Data 控件**：`Connect`/`DatabaseName`/`Recordset`/绑定是 DAO/Jet 语义，原生没有替身；要么引外部引擎（装不起"零预编译依赖"那条既有原则），要么自研一份 Jet 兼容层（那是另一条产品线）。⇒ 保持今天的样子（枚举里有、创建不了），但**要补一条诊断**：见到 `Begin VB.Data` 明确报"本控件未实现"，而不是像现在这样静默跳过（§六-2）。
2. **OLE 容器控件**：`InsertObjDlg`/`CreateEmbed`/`CreateLink`/就地激活/动词菜单 = 一整套 `IOleClientSite` + `IViewObject` 容器实现，工作量超过其余全部之和，且与"走原生控件"无关（它本来就是 OLE）。⇒ 不做，同样补"未实现"诊断。
3. **真 OCX 宿主不拆**：`vb6_OcxHost_Create`（Fix 143）那条路继续留着，谁真拿 MSCOMCTL.OCX 来就照旧能跑；本线只是让**默认路**不依赖它。
4. **系统状态面板与数据绑定**：`Panel.Style = sbrTime/sbrDate/CapsLock/NumLock`、`DataSource`/`DataField` 全不做（前者要键盘状态轮询，后者挂在 Data 线上）。
5. **设计期**：属性页（`BeginProperty`）、右键"自定义"、OLE 拖放、`OLEDragDrop` 系列事件、设计器外观还原 —— 都不做。

### C29-T（VB.Timer 运行期真触发 + 精度提到 ms 级）→ 已出

来源：用户 2026-09-26 追加"把 timer 的精度做高一点"。量下来先决问题不是精度而是**它根本不理运行期**：

- 设计期 `Enabled=0` 的 Timer，cgen 那段 WM_CREATE 注册循环直接**不挂表**（`if (enabled)`）；
- Timer 是无窗口控件（`controlTypeToWin32Class` 返回 nullptr）⇒ `vb6_hwnd_<timer>` 恒 NULL，

  through vb6_SetTimer/vb6_KillTimer" — 那条"实际操控"从来没有人接。

**BASE 实测（同一份判据喂改前的二进制）**：`R1-on20=31`、`运行期开=0`、`改 Interval=100 仍 32`、
`关掉之后还烧 16`、`Interval=5 只到 32`。

1. **身份**：Timer 换成自注册的不可见窗口 `VB6_TIMER`（0x0、清 WS_VISIBLE），与 C29-9 的
   `VB6_COMMONDIALOG` 同一手法 → 好处是 cgen 的 `readFn(hwnd)/writeFn(hwnd, v)` 形状完全不用特判，
   RTL 侧按这个句柄就能找回 `g_timerTable` 里自己那一格。
2. **注册**：只要写了 `Timer1_Timer()` 就照挂表，设计期那个 `Enabled` 当参数交给 RTL 决定起不起

3. **精度**：`SetTimer`（~15.6 ms 地板）换成 winmm `timeSetEvent(wResolution=1)`。到期回调**不**直接

   只是粗）。
4. **两条老坑各撞一次**：布尔 `Enabled` 存 `val+1` 时 VB6 的 True=-1 会变成 0（与"从没设过"不可分辨）
   ⇒ 单独 normalize；`TIME_PERIODIC` 手抄成 0x02（真值 1）会让 `timeSetEvent` 直接失败并**静默退回**
   SetTimer —— 症状只是"精度没上去"，极难归因，改成显式引 `mmsystem.h`（它只是被
   `WIN32_LEAN_AND_MEAN` 排除了）。

### C29-Data 出活：Data 控件（ODBC 后端，2026-09-26 出，判据只本地跑）

### C29-RT-d（2026-09-28）= RichTextBox 的 `Change` / `SelChange`：一条事件的码与 VB6 不同名，另一条的通道会变

### C29-WS（2026-09-28 开工前设计 + 八轮测量）= Winsock 走原生 Winsock2，不碰 MSWINSCK.OCX

用户口径：**用现代化的网络通讯方法实现，顺便把老式 Winsock 控件的坑填掉**。
原生落点 = `ws2_32` 的 Winsock2 API（`getaddrinfo` / 非阻塞 socket + `WSAAsyncSelect`），不是 OCX：
MSWINSCK.OCX 是 32 位 inproc，x64 里 `CoCreateInstance` 直接失败（同 §三 D6 那条硬口径）。

九份探针（`.build/wsprobe1.c` … `wsprobe9.c`，读数同名 `_out.txt` / `wsprobe9_*.txt`）里定的八件事：

1. **通知的种类在消息的 `lParam` 低字里，不在 `WSAEnumNetworkEvents` 里。** 实测 async-select 下
   `WSAEnumNetworkEvents(fd, NULL, &ev)` 回 `rc=0` 而 `ev.lNetworkEvents` **恒 0**、
   `iErrorCode[]` 也全 0（probe3/4/9 三份一致）⇒ 事件类型只能读 `LOWORD(lParam)`
   （`0x1 READ / 0x2 WRITE / 0x8 ACCEPT / 0x10 CONNECT / 0x20 CLOSE`），错误码只能读
   `getsockopt(SO_ERROR)` —— 而且**必须读在枚举之前**：refused 那次 `SO_ERROR-before=10061`，
   枚举之后再问就被清了。这条直接决定 RTL 的 WndProc 形状。
2. **地址解析用 `getaddrinfo(AF_UNSPEC)`，而且必须按链表逐个试。** 本机 `localhost` 的顺序是
   **`::1` 在前、`127.0.0.1` 在后**；字面量 IP 只出一族。只拿第一条 = IPv6-only 的程序，
   老 VB6 源码里写 `RemoteHost = "localhost"` 的那些会连不上（`gethostbyname` 那代 API 只会给 IPv4，
   换 `getaddrinfo` 就必须把"逐个试到成功为止"一起做）。
   失败码：解析不到 → `rc=11001`（`WSAHOST_NOT_FOUND`，`.invalid` 与非法 IP 都是它）；
   **空主机名 → `rc=0`**（gai 拿它当"任意地址"）⇒ "没设 RemoteHost 就 Connect"要 RTL 自己拦。
   这一条也是 **CI 唯一稳定的 `Error` 判据来源**（同步、不需要外网）。
3. **一枚双栈 socket 就够**：`::` + `IPV6_V6ONLY=0` 的监听接得住 IPv4 回环客户端（实测 accept 得到）。
   ⇒ `LocalIP` 留空时默认双栈监听，不再只能 IPv4。
4. **老坑①"DataArrival 里必须 GetData，否则事件反复触发"的根因量到了**：还剩 6 字节没读、
   也没有新数据，400 ms 内 Winsock 自己又投了一条 `FD_READ`（probe3 C2b）。
   现代做法 = **RTL 在通知里一次读到干净**（`FIONREAD` 定长 + 缓冲），把字节数交给 `DataArrival(bytesTotal)`；
   用户不 `GetData` 也不会被反复打扰，数据在缓冲里等他拿。
5. **老坑②"关连接把尾包丢了"也量到了**：`FD_CLOSE` 到达时接收队列里**还有 7 字节**
   （`recv` 先回 7、再 `recv` 才回 0 = 有序关闭）⇒ RTL 先把剩下的读完再发 `Close` 事件。
6. **端口与身份读数**：bind 撞已用端口 → `10048`（ADDRINUSE，够当一条判据）；`bind(port=0)` +
   `getsockname` 得到自动分配的端口；**从没 bind 过的 socket 上 `getsockname` 直接失败** ⇒
   `LocalPort` 读 0、`LocalIP` 读空串（VB6 那台控件在未连接时也是这个观感）；
   刚 `closesocket` 掉的端口立刻再 bind **不需要** `SO_REUSEADDR` 就成（回环实测）。
7. **控件数组那条坑可以正面填**：一枚 socket 配一个自己的身份窗 + 一个自己的消息号，
   实测两类通知互不串（`hits[0]=1 / hits[1]=1`），三条连接各自只收到自己那条（`hits2/3/4=1`）。
   ⇒ VB6 那套"index 0 专职 Listen，`ConnectionRequest` 时 `Load` 新下标再 `Accept`"照搬得动
   （C3 已有控件数组机制），同时**不强制**谁非用数组不可 —— 每枚控件本身就是一台 socket。
8. **进程存活**：`vb6_AnyThreadWindowVisible` 是 `Sub Main` 型程序的常驻判据，而不可见的 0×0 身份窗
   不算"可见窗" ⇒ 只开 Winsock、没有可见窗体的程序不会自己活着（记进手册，别当缺陷查）。

### C29-WS-b（2026-09-28）= Winsock 第二档：TCP 服务端与客户端互为前提的那一整轮

**发出去的**：`Listen` / `ConnectionRequest(requestID)` / `Accept(requestID)` / `Connect` 四条方法

三个形状是被量出来定的（不是照抄 VB6）：

1. **监听面与数据面分开存**（`listenSock` + `sock` + 一条 FIFO `pending`）。老控件把两件事塞进同
   一条 socket ⇒ 服务端 `Accept` 一条之后就听不了。通知归属只能问 `wParam`（实测 = 触发它的那条
   SOCKET）—— 一枚控件此刻最多挂两条 socket，都往同一个窗、同一个私有号投，没有第二个信息源。
2. **`Connect` 是同步逐条候选试到通**：`getaddrinfo("localhost")` 回两条（先 `::1` 再 `127.0.0.1`，
   wsprobe1），而夹具里的监听端是纯 IPv4 ⇒ 只试第一条必然被拒。每条候选用"非阻塞 connect +
   `select(可写)` + `getsockopt(SO_ERROR)`"三件套判成败（wsprobe5 的 V4 那格），最多等 750 ms，
   然后才 `WSAAsyncSelect` —— 挂着异步选择的 socket 上 `select()` 问不出东西（同一格的结论）。
   好处是判据可以紧跟在 `Connect` 那一行之后写，不用等下一个 tick。
3. **`bytesReceived` 每次通知归零**（`vb6_WsDrain` 末尾无条件赋值）。TCP 的 `FD_CLOSE` 会先 drain
   一次，留着上一笔的计数就会凭空多发一次 `DataArrival` —— 这一条在 UDP 那一档根本暴露不出来。

第二条连接（`wsT2.State=7`，握手在系统里真的完成了）之后那条窗**再也没有 0x8**；同窗同号的
数据面事件照收不误（772 的 0x1、0x20 都在），所以不是路由丢了（`route` 全 = 1）。四份探针都
复现不出来：wsprobe10（accept 之后动不动子 socket × 四种）、wsprobe11（照产品的处理顺序，accept
就发生在消息处理器里）、wsprobe12（`drain` × `FIONBIO` 的 2×2）、wsprobe13（`Bind` 那次
FD_READ|FD_CLOSE 与 `Listen` 的 FD_ACCEPT 分两次挂 / 一次挂全）—— 全部 `acceptHits=2`。
已排除：park 时清子 socket 的选择、事后 `FIONBIO`、多控件共用 `(窗, 号)`、mask 改挂、

开工前已经量到、不用再探的六条（探针 `.build/wsprobe14.c`，输出 `.build/wsprobe14_out.txt`）：

1. **不设 `SO_REUSEADDR` 时，两枚 socket 绑同一个 UDP 口 → 第二枚 `bind` 当场 10048**（Q1）。
2. **设了 `SO_REUSEADDR`（= 本控件今天的行为）时，第二枚静默 `bind` 成功**（Q2）⇒ 这是个真坑：
   两枚控件"都自称绑在同一个口"，包只有一边收得到。`Error` 事件要么靠**去掉**这条、要么换
   `SO_EXCLUSIVEADDRUSE`（Windows 上"既要能快速重绑、又要撞口必报错"的正解），二选一要先定。
3. **一条 TCP 周期（listen→connect→accept→先关服务端）之后重绑同一个口：设不设 reuse 都成功**（Q3/Q4）
   ⇒ 为了报错而牺牲快速重绑，在这个形状上不成立，去掉 reuse 没有代价。
4. **阻塞 connect 打一个没人听的回环口：`rc=-1 err=10061`，但耗了 2031 ms**（Q5）
   ⇒ 本控件的 `Connect` 每条候选只等 750 ms ⇒ 这一形现在读出来是 **10060（超时）而不是 10061（拒绝）**。
   `Error` 的编号要照实报，别把超时写成拒绝。
5. **`GetAddrInfoW(L"no-such-host.invalid")` 的 rc 与 `WSAGetLastError()` 同值 = 11001**（Q6）
   ⇒ 解析失败这一格的 Number 有两条来源，取哪条都行，但要写死一条。
6. **`Error` 那七参数的发码形状已经探到**（临时给夹具加一枚 `wsS_Error`，读 `--emit-c` 的原型）：
   `void f(int16_t Number, BSTR* Description, int32_t Scode, BSTR Source, BSTR HelpFile, int32_t HelpContext, int16_t* CancelDisplay)`
   —— `ByVal ⇒ 按值、没写 ⇒ 按指针`这条规则在七参数上同样成立（`Description`/`CancelDisplay` 是指针）。
   RTL 侧要按这个形状调，**x86 真跑验**（本线已三次在 x86 上抓到 x64 看不见的形状错）。
   `Description` 是 ByRef ⇒ 处理器可能改它，释放"回来那一枚"，不是进去那一枚。

另外三条待办的边界（都已写在手册页与 029 前面的格子里）：`SendComplete` / `SendProgress`（要 `FD_WRITE`
那一档，异步 socket 上 `send` 还可能部分发送）、`GetData` 的 Byte 数组那一形、多客户端（卡在
"第二条连接的 `FD_ACCEPT` 在产品里送不到"那条未解的实测上）。

### C29-WS-c（2026-09-28）= Winsock 的 `Error` 事件：把"静默失败"这一族接上

**发出去的**：`Error` 七参数事件（槽位 7 早已留着）+ 五条出错出口统一走 `vb6_WsFail`
（`Bind` 的 socket/地址/撞口三格、`Listen`、`Connect` 的解析失败与"全部候选不通"）+
**撤掉 `SO_REUSEADDR`**。落点仍是同一个 `vb6forms_winsock.c`。

三条读数，每条都会反复咬人：

1. **`closesocket` 会把 `WSAGetLastError()` 清成 0**（Winsock 的规矩：一次成功的 Winsock 调用
   重置上一次的错误码）。第一版出口写成 `closesocket(s); vb6_WsFail(e, WSAGetLastError());`
   ⇒ 事件发出去了、`Number` 却是 **0**，而现场看不出任何异常（State 照样 sckError）。
   ⇒ 一般式：**任何 Winsock 调用一失败，第一件事是把编号抓进局部变量**，再谈清理。
2. **`SO_REUSEADDR` 在 Windows 上是"允许抢口"**：两枚控件绑同一个 UDP 口，第二枚 `bind` **静默成功**
   （wsprobe14 Q2），包只有一份落点 —— 老控件没这个坑（它撞口当场 10048）。撤掉之后 Q1 那条
   "第二枚当场 10048"成立，`Error` 才有确定性来源；而 Q3/Q4 证明"关掉再重绑同一个口"两种设法
   都成功 ⇒ 撤它没有快速重启的代价。
3. **`Error` 那七参数的形状是量出来的**（临时给夹具挂一枚 `wsD_Error`，读 `--emit-c` 的原型）：
   `void f(int16_t, BSTR*, int32_t, BSTR, BSTR, int32_t, int16_t*)` —— `ByVal ⇒ 按值、没写 ⇒ 按指针`
   在七参数上同样成立，而 **把 String 形参存进模块变量是指针拷贝**（`gErrD = (*Description);`），
   RTL 在调用返回后释放原串 ⇒ 存下来的那一格变悬垂指针（实测读出 `"WS38="` / `"Y"` 这种别人用过的堆块）。
   ⇒ 另立缺陷 #113；本批评据一律**当场问长度**（`Len(Description)` / `Len(Source)` 记进 Long），
   要留串就 `Description & ""` 复制走 —— WS40 钉的正是"复制过的那份在 RTL 放手之后仍读得到"。
