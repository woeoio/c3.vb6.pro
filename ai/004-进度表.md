## P10 - RTL 内嵌与编译流程封闭

> 目标：将 RTL 运行时库（.lib + 精简头文件）作为 Windows 资源嵌入 c3.exe，编译时释放到临时目录，编译完成后自动清除。用户分发只需 c3.exe，不再需要 rtl/ 目录和 VB6RTL_DIR 环境变量。彻底隐藏 C 语言转译实现细节，体验与 VB6 一致——开箱即用，编译过程不透明。
>
> 绝不暴露中间产物，不保留 --keep-intermediate 开关。编译问题时仅写调试日志供开发者分析。对外宣发也不提及 C 语言转译话术。

### 核心设计

- **构建时（开发侧）**：src/rtl/core/\*.c -> MSVC 编译为 4 组 .lib（vb6rtl.lib / vb6com.lib / vb6comserver.lib / vb6forms.lib）；头文件精简为纯声明版（仅保留函数原型、结构体定义、必要宏，删除所有函数体、内部宏、实现注释）；.lib + 精简.h 通过 Windows RC 资源嵌入 c3.exe
- **编译时（用户侧）**：c3 在 %TMP%\C3C\{时间戳}\ 创建会话目录 -> 生成用户 C 代码 -> 从内嵌资源释放 RTL .lib + .h -> shell-out MSVC 编译链接 -> 复制最终 .exe/.dll 到用户指定输出路径 -> 清除临时目录所有内容
- **崩溃残留清理**：c3 每次启动时扫描 %TMP%\C3C\ 下所有子目录，删除时间戳超过 300 秒（5 分钟）的旧会话目录
- **编译失败处理**：失败时将临时目录中的用户 .c 代码片段、MSVC 编译器错误输出、c3 自身诊断信息写入 c3-error.log（存放在用户项目目录），不保留 RTL 文件，不保留中间 .obj/.lib
- **禁用中间产物保留**：不提供 --keep-intermediate 或类似开关。一切编译问题由开发者通过日志分析发给我这里解决

### P30 扁平化UI引擎（--flat-ui 编译参数）

> 目标：通过 Owner-Draw 机制美化 VB6 基础控件，编译参数 --flat-ui 一键启用，原生控件行为（事件/消息）完全不变，仅替换渲染层。
> 设计文档：待 P30 启动时编写
> 基线：82/82 回归零失败

#### 分级实施方案

| L2 全控件优化 | +TextBox/ComboBox/ListBox/HScrollBar/VScrollBar            | ~1000行     | 1px边框+聚焦高亮+扁平下拉箭头+自定义滚动条           | P1 二批 |
| L3 主题引擎   | +主题文件(JSON配色)+多配色方案+动画过渡(悬停淡入/按下涟漪) | ~2000行     | 多主题切换(亮/暗/自定义)+圆角全局统一+动画           | P2 远期 |

#### 编译参数设计

`--flat-ui                       启用扁平化UI（默认配色）
--flat-ui --ui-accent=038DD6   指定强调色（6位HEX，默认科技蓝）
--flat-ui --ui-radius=6        指定圆角像素（默认4px）
--flat-ui --ui-theme=dark      指定主题预设（default/dark/custom）`

#### 技术要点

- **Owner-Draw 机制**：编译时给目标控件加 BS_OWNERDRAW 风格位，运行时 WM_DRAWITEM 分发自定义绘制
- **状态追踪**：复用现有子类化机制，追踪 hover/pressed/focused 状态（WM_MOUSEMOVE/WM_MOUSELEAVE）
- **配色可定制**：编译期生成 #define VB6_UI_CLR_xxx 常量，用户可通过编译参数覆盖
- **TextBox 特殊处理**：L2 实现，拦截 WM_NCPAINT 绘制边框，内部渲染仍由系统处理
- **零影响保证**：无 --flat-ui 时行为完全不变，纯增量，零回归风险

#### 实施原则

- L1 先行（按钮类+Frame），投入产出比最高，用户视觉感知最强
- 每个 Level 独立验证回归，不跨级推进
- 主题引擎(L3)待 L1/L2 稳定后再启动
